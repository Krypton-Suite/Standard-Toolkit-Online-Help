Krypton Designer Editors

Overview

The Standard Toolkit ships a set of public WinForms UITypeEditor / CollectionEditor types under the Krypton.Toolkit namespace. They replace (or parallel) the classic System.ComponentModel.Design / System.Windows.Forms.Design editors with Krypton-themed dialogs:

  • Modal KryptonForm chrome
  • Shared footer button bar (PanelAlternate, theme combo, OK/Cancel)
  • Shared content host (PanelClient)
  • DPI scaling via KryptonDesignerEditorDpi
  • Local theme selector that restyles only the open editor dialog (not the edited component or KryptonManager global palette)

Package: Krypton.Toolkit
Namespace: Krypton.Toolkit

Consumers can apply these editors to their own components and controls with [Editor(typeof(...), typeof(UITypeEditor))], or subclass the collection editor bases to build custom collection UIs.

This guide covers architecture, the public API surface, usage patterns, theming/DPI, edge cases, and how to validate editors at design time.

Layering

Layer Role
Concrete editors UITypeEditor / CollectionEditor subclasses applied via [Editor]
Collection bases KryptonDesignerCollectionEditor → optional KryptonDesignerStandardCollectionEditor
Dialog chrome KryptonDesignerCollectionForm, content panel, button bar
Services Theme resolution (KryptonDesignerEditorTheme), DPI (KryptonDesignerEditorDpi)

Design-time data flow (collection editors)

  1. Property grid opens the editor → EditValue(context, provider, value).
  2. KryptonDesignerCollectionEditor creates a KryptonDesignerCollectionForm and calls InitializeEditValue(value).
  3. The form clones/copies items into a working set; the user edits list + property grid.
  4. On OK, the form must call CommitDesignerItems() (sets Items then ApplyDesignerItems / SetItems) and typically Context.OnComponentChanged().
  5. EditValue returns the (possibly updated) collection instance to the property grid.

Theme changes in the footer combo only call KryptonDesignerEditorTheme.ApplyToForm on the dialog. They do not write back to the edited control’s PaletteMode or to KryptonManager.GlobalPaletteMode.

Prerequisites for consumers

  1. Reference Krypton.Toolkit (NuGet package or project reference).
  2. Target a Windows WinForms TFM supported by the toolkit (e.g. net472, net8.0-windows).
  3. Use design-time attributes from System.ComponentModel / System.Drawing.Design:
using System.ComponentModel;
using System.Drawing.Design;
using Krypton.Toolkit;

The Visual Studio / .NET designer must be able to load Krypton.Toolkit at design time (same as for any other Krypton control).

Quick start — apply an existing editor

using System.ComponentModel;
using System.Collections.Specialized;
using System.Drawing;
using System.Drawing.Design;
using Krypton.Toolkit;

public class MyWidget : Component
{
    [Category("Appearance")]
    [Editor(typeof(KryptonDesignerMultilineStringEditor), typeof(UITypeEditor))]
    public string Notes { get; set; } = string.Empty;

    [Category("Appearance")]
    [Editor(typeof(KryptonDesignerImageEditor), typeof(UITypeEditor))]
    public Image? Icon { get; set; }

    [Category("Data")]
    [DesignerSerializationVisibility(DesignerSerializationVisibility.Content)]
    [Editor(typeof(KryptonDesignerStringCollectionEditor), typeof(UITypeEditor))]
    public StringCollection Tags { get; } = new StringCollection();
}

Drop-down vs modal style is decided by each editor’s GetEditStyle (for example image index is drop-down; multiline and most collections are modal).

Toolkit-specific (not general-purpose)

These remain specialized to Krypton types (breadcrumbs, check-sets). Prefer the shared public editors or subclass the bases for your own models:

  • Breadcrumb items editor (internal dialog specialized to KryptonBreadCrumbItem)
  • Check-button collection editor (requires KryptonCheckSet)

Feature deep-dive

Theme resolution and the footer combo

KryptonDesignerEditorTheme.ResolveFromContext / ApplyFromContext:

  1. Prefer the owning component’s local palette when it is a VisualControlBase / palette-aware type and mode is not Global.
  2. Otherwise use KryptonManager.CurrentGlobalPaletteMode (and custom global palette if applicable).

KryptonDesignerEditorButtonBar.Create(owner, ok, cancel) adds a theme combo that calls ApplyToForm on the editor form only. Changing Microsoft 365 Blue → another theme in the dialog does not mutate the design surface control.

Content panel and button bar

var layout = new TableLayoutPanel { Dock = DockStyle.Fill, BackColor = Color.Transparent };
// ... add content ...

Controls.Add(KryptonDesignerEditorContentPanel.Create(this, layout));
Controls.Add(KryptonDesignerEditorButtonBar.Create(this, okButton, cancelButton));

Recommendations:

  • Set WinForms layout containers (TableLayoutPanel, FlowLayoutPanel) to BackColor = Color.Transparent so they do not paint a hard strip over PanelClient.
  • For Krypton panel hosts used only for spacing, set StateCommon.Color1 = Color.Transparent when they should not fill solid.

DPI

ClientSize = KryptonDesignerEditorDpi.Scale(this, new Size(640, 420));
MinimumSize = KryptonDesignerEditorDpi.Scale(this, new Size(520, 320));

KryptonDesignerCollectionForm already calls Configure on load and ApplyOnShown when shown. Custom modal KryptonForm editors should mirror that pattern.

Persistence (collection editors)

Required on OK: assign Items then CommitDesignerItems(), then notify the designer:

Items = rootItems;
CommitDesignerItems();
Context?.OnComponentChanged();

Setting Items alone does not write into the edited collection instance. Forgetting CommitDesignerItems causes “edits disappear after close/reopen”.

Standard list editors (KryptonDesignerStandardCollectionEditor) already do this in their OK handler.

ButtonSpec collections

KryptonDesignerButtonSpecAnyCollectionEditor:

  • Constructed for ButtonSpecAny (specialized subclasses pass another item type).
  • Overrides CreateNewItemTypes, friendlier GetDisplayText (Text → UniqueName → Type), and SetItems via IList.Clear/Add.

Use it on properties of type ButtonSpecCollection<> (or other IList of specs) with DesignerSerializationVisibility.Content.

Building a custom collection editor

Minimal subclass of the standard list editor

using System.Collections;
using System.ComponentModel;
using System.Drawing.Design;
using Krypton.Toolkit;

public sealed class WidgetCollectionEditor : KryptonDesignerStandardCollectionEditor
{
    public WidgetCollectionEditor()
        : base(typeof(WidgetItem))
    {
    }

    protected override Type[] CreateNewItemTypes() =>
        new[] { typeof(WidgetItem), typeof(WidgetItemSpecial) };

    protected override string GetDisplayText(object? value) =>
        value is WidgetItem item && !string.IsNullOrEmpty(item.Name)
            ? item.Name
            : base.GetDisplayText(value);

    protected override object? SetItems(object? editValue, object[]? value)
    {
        if (editValue is IList list)
        {
            list.Clear();
            if (value != null)
            {
                foreach (var entry in value)
                {
                    list.Add(entry);
                }
            }

            return editValue;
        }

        return base.SetItems(editValue, value);
    }
}

// On the owning type:
public class WidgetHost : Component
{
    [DesignerSerializationVisibility(DesignerSerializationVisibility.Content)]
    [Editor(typeof(WidgetCollectionEditor), typeof(UITypeEditor))]
    public WidgetItemCollection Items { get; } = new WidgetItemCollection();
}

Pass the item type to base(...) (same pattern as framework CollectionEditor), not the collection type, unless your specialized overrides of GetItems/SetItems expect the collection type (legacy Ribbon editors sometimes pass collection types — prefer item type for new code).

Fully custom dialog (tree + property grid, etc.)

  1. Subclass KryptonDesignerCollectionEditor.
  2. Override CreateKryptonDesignerCollectionForm() to return your KryptonDesignerCollectionForm subclass.
  3. In the form:
    • Build UI with transparent layout panels + content panel + button bar.
    • On load/open: ApplyOwnerPaletteFromContext() (or custom palette logic).
    • On OK: set Items, CommitDesignerItems(), designer change notification.
  4. Optionally override CreateNewItemTypes, CreateInstance, DestroyInstance, GetDisplayText, SetItems, GetItems.

Site services for nested property editors

Collection forms that host KryptonPropertyGrid typically assign:

_propertyGrid.Site = new KryptonDesignerPropertyGridSite(Context, _propertyGrid);

(or an equivalent ISite) so nested editors (images, resources) can resolve IDesignerHost and related services.

Editor style reference

Style How opened Examples
UITypeEditorEditStyle.Modal Ellipsis → modal form Multiline, Image Select Resource, most collections
UITypeEditorEditStyle.DropDown Dropdown arrow Image index/key, masked-text helper, data-binding picker

Always implement GetEditStyle to return None when context?.Instance is unsuitable (multi-select object arrays often cannot edit safely).

Edge cases and limitations

Scenario Guidance
List control Items with DataSource set Use KryptonDesignerListControlStringCollectionEditor — it throws a clear ArgumentException
Image properties in class libraries Project resource enumeration is best-effort; import path still works
High DPI Prefer KryptonDesignerEditorDpi.Scale; avoid hardcoded 96-DPI sizes for button bars
Binary compatibility Prefer adding public editors; do not rename existing public editor types
C# / TFM Toolkit consumers may use modern C#; toolkit implementation remains constrained for older TFMs
Designer process Editors must not assume they run in the app process only; avoid UI that requires runtime-only state
Serialization Collection properties still need DesignerSerializationVisibility.Content (and usually ShouldSerialize* / Reset* if you follow Krypton patterns)

Remaining native editor migration (maintainers)

Many properties still carry // ToDo V120 LTS: where attributes still point at native editors even though Krypton equivalents exist. High-value follow-ups:

  • Wire KryptonDesignerMultilineStringEditor / StringArrayEditor at remaining MultilineStringEditor sites
  • Wire data-member / format-string / image-index / tree-node / ListView editors where ToDos remain
  • Retire legacy multiline hosts when attribute migration is complete

Do not add ToDos for chrome polish (transparent layouts, focus, theme combo) once shipped.

Validation

In Visual Studio

  1. Create a WinForms project referencing Krypton.Toolkit.
  2. Add a component/control with [Editor(typeof(KryptonDesigner...), typeof(UITypeEditor))] on a property.
  3. Open the form designer → select the component → open the property editor (ellipsis / drop-down).
  4. Confirm:
    • Krypton chrome and footer theme combo
    • Changing theme restyles the dialog only
    • OK keeps values after reopen; Cancel discards
  5. For collections: Add/Remove, property grid edits, and designer serialization after save.

Toolkit sample

Use Source/Krypton Components/TestForm where demos expose properties that use these editors (breadcrumb items, button specs, images, etc.).

API summary cheat sheet

Apply simple editor:
  [Editor(typeof(KryptonDesignerX), typeof(UITypeEditor))]

Standard collection:
  class MyEditor : KryptonDesignerStandardCollectionEditor
    ctor → base(typeof(MyItem))
    optional: CreateNewItemTypes, GetDisplayText, SetItems

Custom collection dialog:
  class MyEditor : KryptonDesignerCollectionEditor
    CreateKryptonDesignerCollectionForm() → MyForm : KryptonDesignerCollectionForm
    On OK: Items = ...; CommitDesignerItems(); Context.OnComponentChanged();

Chrome:
  KryptonDesignerEditorContentPanel.Create(form, content)
  KryptonDesignerEditorButtonBar.Create(form, ok, cancel)
  KryptonDesignerEditorTheme.ApplyFromContext(form, context)
  KryptonDesignerEditorDpi.Scale(form, size)
